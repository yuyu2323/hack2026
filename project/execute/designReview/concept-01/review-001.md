## 3. 촬영·재검수 요청

모바일 점주 홈·사진 제출·실제 결과 상단/기준근거/Reference·재제출 비교, desktop 영업 첫 화면·사진 근거·조치·기준/Reference 관리·추이/결측·운영 첫 화면·계정/연결·attempt/감사를 `fullPage:false`의 구간별 PNG로 확인한다. unknown/기술실패·키보드 초점·200% 확대·직접 URL/권한 철회는 해당 상태별 캡처와 실제 조작 기록이 필요하다. 01은 별도320/768/1024 breakpoint를, 모든 시안은 docs09의360/1280을 포함한다. 비밀번호·인증값은 캡처하지 않는다.

소스 수정 후 각 발견 사항의 같은 기준으로 재검수하며 기능 PASS를 디자인 PASS로 대체하지 않는다. 최종 캡처 전 HTML 매뉴얼 완료를 선언하지 않는다.

## 4. 통합 수정 소스 재검수

통합 작성자 수정 소스 재확인: SnapshotReferences에 referencePhotos를 전달하며 reference_id로 실제 Photo를 매칭한다. 관리뷰는 reference-management-list/row, desktop160px 썸네일+본문 행 및 mobile단열로 변경되었다. D01-P01/P02의 소스 불일치는 해소되었고 실제 캡처 재검수는 대기한다. 테스트6+9·build PASS 보고 수신.

수정 이후 hash는 [review-source-002.json](review-source-002.json)에 보존한다. 위 최초 발견 표는 발견 당시 기록으로 유지하며 최종 시각 판정은 기준별 표에서 별도로 갱신한다.
