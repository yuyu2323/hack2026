## 1. 컨셉과 판단 기준

첫 화면에서 전체 규모·확인할 문제·원본 근거의 관계를 읽게 한다. `범위 선택 → 지표 → 목록 → 근거 → 조치`가 주 탐색 구조다. 영업 관리자는 담당 매장 간 우선순위를 판단하고, 점주는 최근 상태와 다음 제출을 찾으며, 운영자는 장애·연결 누락을 기술 메타데이터로 추적한다.

모든 데이터를 카드로 분리하지 않는다. 지표는 얕은 수평 스트립, 목록은 열이 정렬된 표, 평가 근거는 사진+기준의 고정 구획으로 표현한다. 간결한 행과 동일 필터를 유지한 상세 이동이 핵심이다. dense table이 모바일에서 가독성을 해치지 않게 점주 화면은 요약 행 카드로 전환한다.

이 시안은 오늘 할 일 보드(02), 사진 전면 탐색(03), 단계별 현장 wizard(04), 트리/다중비교 workspace(05)와 달리 **숫자와 행의 관계로 관제하고 필요한 건을 선택한 뒤 원본을 확인**한다. 단순 테마 차이가 아니다.

## 2. 역할별 정보 구조

| 역할 | 시작 화면 및 메뉴 순서 | 업무 우선순위 |
|---|---|---|
| 점주 | 현황 → 사진 제출 → 제출 이력 → OFC 문의 → 알림 | 선택 매장, 새 점검 CTA, 진행 중/최근 결과, 확인할 조치 |
| OFC | 관제 → 담당 매장 → 제출 이력 → 확인 필요 → 진열 기준 → Reference → 분석 → 알림 | 담당 범위의 확인 필요/미해결 → 개별 근거 → 조치 → 후속 결과 |
| 지역 | 관제 → 지역 매장 → 제출 이력 → 확인 필요 → 진열 기준 → Reference → 분석 → 알림 | 같은 지역 매장 비교와 반복 개선 항목, 지역 기준 보완 |
| 본사 | 관제 → 전체 매장 → 제출 이력 → 확인 필요 → 진열 기준 → Reference → 분석 → 알림 | 지역/카테고리 필터를 통한 전사 상태, 기준 및 Reference 버전 |
| 운영자 | 서비스 상태 → 작업 처리 → 계정·연결 → 기준 정보 → 운영 이력 → 운영 공지 | 가용 상태/작업 실패·연결 오류 → 복구/정정 → 감사 확인 |

로그인 뒤 현재 역할의 메뉴만 제공한다. 사용자 프로필에는 역할과 현재 범위·로그아웃만 두며 역할 전환으로 권한을 얻는 UI는 없다. 운영자에게 사진·기준 본문·매출·평가 메뉴를 보여 주지 않는다.

## 3. 화면 구성과 주요 동선

모든 canonical 라우트와 S-* 화면을 [04 §2](../../../docs/04-screens.md)에서 상속한다. 각 컨셉은 같은 기능을 제공하며 아래의 차이는 화면 배치다.

1. **점주**: `/store-owner`의 상단 매장 선택과 큰 “사진으로 점검하기” → `/submit`의 한 페이지 폼(사진 중심, 선택 질문) → 상세의 처리 상태 → 결과의 개선 필요 항목 → “개선 후 다시 제출” → 이전/이후 비교. 최근 제출 목록에서 어느 단계든 다시 열 수 있다.
2. **OFC**: `/ofc-admin` 범위와 기간 확인 → “OFC 확인 필요” 지표 → 동일 필터가 선택된 제출 목록 → 상세 사진/근거/기준 버전 → 연결 이슈 조치 → 재제출 이력. 담당 매장 후보 등록은 매장 화면의 보조 동작이다.
3. **지역·본사**: 관제 범위필터 → 매장표의 같은 열 비교 → 매장 상세 → 평가 기준 확인 → 새 진열 기준 버전 저장 → 이후 제출에 적용, 과거 결과 snapshot 확인 → 분석 화면의 추이/Mock 상관/기간표.
4. **플랫폼 운영자**: 서비스 상태의 실패 수 → 실패 목록 → 작업 메타데이터·attempt 표 → 실패 종료/재처리 가능 확인 → 사유 입력/재처리 → 새 attempt 상태 → 운영 이력. 사진/질문을 보지 않고 수행한다.
5. **접근 정정**: 계정·연결 목록 → 일반 계정 상세 → 변경 영향 요약·사유 → 저장 → 현재 role/mapping 반영 → 감사 이력. 사용 중 master 비활성은 과거 기록 유지 문구와 함께 수행한다.

## 4. 사용 환경과 매뉴얼

- 점주 기본 검수: 390×844, 큰 터치 영역, 업로드 input/카메라 지원 브라우저의 선택 기능, 정상 파일선택 대안.
- 관리자 기본 검수: 1440×900, 왼쪽 탐색·상단 필터·표·2열 상세. 좁은 화면에서는 역할 메뉴 drawer와 단일 열로 전환한다.
- 공통: 키보드, 200% 확대, 긴 한국어 문구, 5장 사진, 빈/로딩/기술실패/판단불가를 검수한다.
- 실행: `web-concepts-01`에서 dev/build/preview 한 단위, 로컬 5173. 공통 API·worker·AI 서버 필요.
- 매뉴얼: `deliverables/manuals/concept-01/index.html`. “관제 데스크”의 실제 메뉴와 위 5개 역할 동선을 캡처하며 다른 시안 이미지를 재사용하지 않는다. 최종 선택은 사람에게 남긴다.

## 5. 미확정·인계

공통 API 계약의 세부 필드·독립 문서 검토를 통과하고 G1 확정되었다. 개발자는 확정 및 이 명세 버전을 기록한 뒤 구현한다. 독립 디자인 검수자는 본 디자인 작성/구현/기능 QA 담당자와 분리한다. 기능·보안 범위를 낮추는 디자인 변경은 허용하지 않는다.
