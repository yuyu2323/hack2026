## 3. root 진행 입력 검수의 경로와 기대

공통 점주 경로는 포트5173/5174/5175/5176/5177의 `/store-owner/submit`. 로그인된 담당 매장·활성 카테고리를 사용한다. 유효한 최종 제출 버튼까지 누르면 모델이 호출될 수 있으므로 이 경계 검수에서는 유효5장 상태를 확인한 뒤 삭제/오류 상태만 검증한다. 이미 실제 제출의 busy·단일접수 증거가 있으므로 추가 정상 제출은 필요 없다.

질문은 실제 키 입력2000자에서 추가 키가 제한되고 한글 줄바꿈/화면 폭/오류가 읽히는지 확인한다. CUA 문자열 직접 삽입이 maxlength를 우회한2002자 관측을 실제 키 제한 결함으로 세지 않는다. 질문을 비워도 선택 질문으로 안내되는지 확인하되 새 모델 호출은 하지 않는다. 빈 매장/이력과 기준0/Reference0은 서로 다른 상태이므로 한 캡처로 대신하지 않는다.

## 5. poll 종료·없음 상태의 가장 작은 확인

**새 작업 생성 없이**, 각 시안의 기존 `/store-owner/submissions/{id}` 또는 권한 있는 `/ofc-admin/submissions/{id}`에서 이미 succeeded 기록1개와 failed 기록1개를 사용한다. 상세가 안정된 뒤 페이지를 이동/포커스 변경하지 않고 약6초 관찰하여 **해당 submission detail GET**이2초마다 반복되지 않는지 기록한다. 계정/me의10~15초 갱신·이미지 요청을 job polling으로 세지 않는다. 04는 interval이0으로 바뀔 때 마지막1회 조회가 있을 수 있으므로 안정화 이후를 본다. 새로고침/복귀로 한 번 다시 읽는 것은 종료실패가 아니다. 권한 철회 시 데이터 제거는 기존E04로 입증됐으므로 다시 계정을 비활성화하지 않는다.

현재 정책/소스에서 terminal2초 반복의 구체 결함은 찾지 못했다. 03/04/05 각각의 effect/timeout cleanup과01 callback은 종료상태를 처리한다. API 요청 수 관찰 수단이 없으면 임의 화면 정지만으로 “poll 종료 PASS”라고 쓰지 않고, 소스/단위 증거와 실제 브라우저 미측정을 구분한다. timer scheduler 세부 경쟁은 컴포넌트 fake-clock 회귀 대상이지 추가 worker/모델 실행 대상이 아니다.

기준/Reference 없음은 root가03/04에서 이미 사용한 기존 Mock `no-criteria-reference` 제출을01/02/05의 허용 영업 상세에서 열면 된다. 01 `적용 기준 · Reference` 탭,02 제출 당시 기준·Reference 구간,05 `제출 당시 적용 기준`을 확인한다. 기준0/Reference없음 이유·OFC확인·null을0점으로 만들지 않는 상태만 남기며 이를 새 실제 AI 정확도 검증으로 세지 않는다. 긴 기준 역시 기존 긴 본문이 있는 상세를 열어 전체읽기/줄바꿈만 확인하고 새10000자 기준을 모델에 보내지 않는다.

## 6. 완료 기록의 최소 단위와 제외

후속 기록은 시안·역할·route·viewport·실제 행동·기대/관찰·PASS/FAIL/NOT_RUN·관련 PNG 또는 요청횟수만 남긴다. 원시 네트워크 헤더/토큰·비밀번호·실제 운영 자료는 남기지 않는다. 한 정상사진 캡처로6장/용량/CSRF/409까지 통과로 확장하지 않는다.
