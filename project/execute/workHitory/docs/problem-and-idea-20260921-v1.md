# StoreLoop — 매장 사진을 근거 있는 판단과 현장 개선으로 연결하다

StoreLoop는 **본사·지역·OFC가 여러 매장의 확인 필요 사항과 개선 우선순위를 파악하고, 점주가 AI 피드백을 받아 조치한 뒤 그 결과까지 확인하는 매대 운영·관제 플랫폼**입니다. OFC는 여러 점포의 운영을 지원하는 현장 담당자입니다.

**우리가 해결하려는 문제는 매장 상태를 확인하는 일과 개선 결과를 관리하는 일이 끊어져 있다는 것입니다.** 점주가 매대 사진을 보내 진열 상태를 문의해도, 적용 기준·담당자의 답변·실제 조치·개선 후 사진이 여러 채널에 흩어지면 같은 설명과 확인이 반복됩니다. 여러 점포를 지원하는 OFC는 먼저 확인할 매장을 찾기 어렵고, 본사·지역 담당자는 어떤 기준이 현장에서 반복적으로 문제가 되는지 일관된 근거로 파악하기 어렵습니다.

예를 들어 스낵 매대의 진열을 문의한 건이라면, 점주는 어느 위치를 왜 정리해야 하는지, OFC는 어떤 근거로 안내했고 후속 확인이 필요한지, 본사는 같은 문제가 다른 매장에서도 발생하는지 알아야 합니다. StoreLoop는 이 세 판단이 같은 사진·기준·이력에서 이어지도록 설계합니다.

**해결 아이디어는 운영 기준과 현장 사진을 비교한 AI 피드백을 담당자의 업무와 후속 결과에 연결하는 것입니다.** 본사·지역·매장·매대별 가이드라인과 우수 매대 사진인 Reference를 등록하고, 점주가 제출한 사진·질문에 적용합니다. AI는 확인할 위치, 관찰 근거, 개선 행동과 판단 한계를 제시합니다. 판단하기 어려운 부분은 OFC의 검토로 연결하고, 점주가 조치 후 새 사진을 제출하면 이전 제출과 함께 변화를 확인합니다.

대표 흐름은 다음과 같습니다.

1. 점주가 담당 매장의 스낵 매대 사진과 질문을 제출합니다.
2. AI가 적용 기준·Reference와 비교하여 확인할 위치와 이유를 보여줍니다.
3. OFC가 대시보드에서 해당 건의 사진·평가 근거를 확인하고 검토·조치 상태를 기록합니다.
4. 점주가 조치 후 새 사진을 제출하고, 담당자가 이전 결과와 후속 결과를 확인합니다.
5. 사진·적용 기준·AI 판단·검토·조치·후속 제출이 연결된 이력으로 남습니다.

빈 공간이 보인다는 관찰과 실제 품절 여부를 구분하고, AI의 판단과 담당자의 확인을 각각 기록합니다. 이렇게 축적한 근거와 이력은 이후 문의 대응, 운영 기준 보완, 매장별 지원 우선순위 판단에 활용할 수 있습니다.

**사업의 목표는 매장 점검과 지원을 공통 근거에 따라 운영하고, 그 과정에서 재사용할 수 있는 운영 지식을 축적하는 것입니다.** 점주는 다음 행동을 구체적으로 이해하고, OFC는 확인이 필요한 매장에 지원 역량을 배분하며, 본사·지역은 현황과 반복 문제를 비교해 기준을 개선하도록 돕습니다. 플랫폼 운영자는 계정·담당 연결·분석 장애를 관리하여 이 업무가 지속되도록 지원합니다.

도입·확장 전략은 세 단계입니다.

- **사진과 기존 기준으로 시작합니다.** 초기 도입 대상은 여러 점포를 지원하는 본사·지역·OFC 조직입니다. 스마트폰 사진과 이미 운영 중인 진열 기준을 활용하고, 반복 문의가 많은 1~2개 카테고리부터 작은 점포군에서 시험합니다. 현장에는 사진 제출과 다음 행동 확인을, 관리 조직에는 우선순위와 근거 조회를 제공합니다.
- **사용성과 운영 효과를 측정한 뒤 확대합니다.** 사진 제출부터 피드백까지의 시간, OFC의 건별 검토 시간, 이슈 처리 시간, 재문의·누락·잘못된 피드백, 분석당 비용을 확인합니다. 실제 전후 사진과 담당자 확인으로 개선 결과를 검토하고, 결과에 따라 기준과 화면·업무 절차를 보완합니다.
- **검토된 기록을 운영 지식으로 발전시킵니다.** 적용 매장과 카테고리를 넓히고, 이후 실제 매출·재고 등 운영 데이터와 연결해 기준과 지원 방식의 효과를 검토합니다. 장기적으로 자동 관측과 매장 내 AI, AI·로봇의 작업 판단에 활용할 수 있는 상태·기준·조치·결과 데이터를 축적하는 방향을 지향합니다. 이 확장은 별도의 현장·비용·기술 검증을 거쳐 추진합니다.

**이번 해커톤에서 구현할 문제는 ‘사진으로 발견한 확인 사항이 담당자의 판단과 후속 확인까지 이어지지 않는 문제’입니다.** 구현 목표는 **기준·Reference 등록 → 사진·질문 제출 → 실제 AI 분석 → 관제·근거 확인 → 검토·조치 → 새 사진 재제출·전후 비교 → 이력 조회**를 하나의 서비스에서 실행하는 것입니다.

가상 매장 5~10개와 초기 카테고리 1~2종을 대상으로 점주·OFC·지역·본사·플랫폼 운영자 5개 역할을 제공합니다. 계정과 담당 범위, 가이드라인·Reference, 사진과 분석 이력, 앱 내부 알림, 기간별 집계를 연결합니다. 매출·재고는 Mock 데이터를 사용하고, 상관분석은 계산과 조회 기능을 시연합니다. 실제 영업 시스템 연동, 카메라·로봇 제어와 현장 매출 효과 검증은 후속 단계로 둡니다.

공통 백엔드와 실제 이미지 모델을 호출하는 별도 AI 분석 서버를 연결합니다. 동일한 기능을 관제·오늘의 업무·사진 근거·모바일 현장·탐색과 비교의 다섯 관점으로 구현해, 사용자가 업무에 맞는 화면 구성을 비교하고 선택하도록 합니다. 각 시안에는 실제 이용 화면에 맞는 HTML 매뉴얼을 제공합니다.

**해커톤의 성공 여부는 심사위원이 대표 업무를 끝까지 실행하고, 그 결과와 근거를 확인할 수 있는지로 판단합니다.** 각 시안에서 실제 AI 분석과 저장·재조회가 연결되는지, 담당 밖 매장의 접근이 차단되는지, 판단 불가와 기술 실패가 구분되는지, 실패를 재처리해도 이전 이력이 보존되는지 검증합니다. 새 사진과 이전 제출의 연결, 대시보드와 상세 목록의 수치 일치, 재시작 후 데이터 보존도 확인합니다.

개발은 하나의 `/goal`과 공통 계약 아래 결과 단위로 에이전트에게 위임합니다. 개발 담당과 독립된 기능 검증·디자인 검수를 거치고, 실패·수정·재검증 기록을 남깁니다. 시연 이미지는 AI 생성 이미지로, 가상 수치는 Mock으로 표시하며, 실제 모델 실행 결과와 구분합니다. 응답 속도는 측정 결과로 보고하고, 현장 시간 절감·매출 개선·진열 개선율은 후속 파일럿에서 확인할 사업 지표로 제시합니다.
