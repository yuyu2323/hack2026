# 시안 05 독립 브랜치 적용 범위

사용자 승인에 따라 이 브랜치는 공통 백엔드·AI·공유 클라이언트와 `web-concepts-05`만 유지한다. 아래 5개 시안 완료 규칙과 docs/00~02는 원래 main의 역사적 기준이다. 이 브랜치의 실행·검증 범위는 README.md와 docs/10-execution.md를 따른다. 원본 계약은 수정하지 않는다.

# StoreLoop 협업 규칙

기준은 docs/00-vision.md → docs/01-architecture.md → docs/02-development-orchestration.md 순서다. 세 문서는 명시적 사용자 승인 없이 수정하지 않는다. 제품은 StoreLoop이며 공통 FastAPI 업무 서버·PostgreSQL·독립 worker·로컬 Codex AI 서버와 React 시안 5개다. 각 시안 단일 빌드에 점주·영업·플랫폼 운영자 화면을 포함한다. 역할별 소스/라우트/메뉴/서버 권한을 분리한다.

- 작업 전 execute/checkList/{module}/{task}.md, 작업 중 execute/workHitory/{module}/{task}.md를 작성한다. 기존 workHitory 철자를 유지한다.
- 문서 공통 계약 게이트 G1 확정 전에 서비스 소스·모델·마이그레이션을 구현하지 않는다. 확정 후 추가 사용자 승인 없이 TDD→구현→검증을 진행한다.
- 독립 작업은 서브에이전트에 배정한다. 구현자와 독립 검토자를 분리한다. 오케스트레이터의 소유권 표를 따르고 같은 파일 동시 편집을 금지한다. 모델/마이그레이션 소유자는 한 명이다.
- 후속 문서 변경은 이유·영향·검증 계획을 먼저 기록하고 영향 담당에게 메시지로 전달해 확인·반영·재검증을 추적한다.
- 테스트·브라우저·실제 AI 검증 결과를 구분하고 미실행을 통과로 쓰지 않는다. Mock은 표시한다. 실제 AI 실패를 고정 응답으로 대체하지 않는다.
- 코드 식별자는 영어, 주석·작업 기록·커밋 메시지는 한국어를 사용한다.
- 기존 변경·프로젝트 밖 자료를 보존한다. 사용자 비밀·실제 비밀번호·토큰·민감 사진은 소스/로그/캡처/커밋에 넣지 않는다.
- Git stage/commit/branch 작업은 root만 수행한다. 원격 공개·push·merge는 별도 부여 권한 없이는 하지 않는다.
- 완료에는 Must·Should, 5개 빌드/실제 API 연결, PostgreSQL 동시성, 실제 AI 5개 시안 인수, 독립 기능·보안·디자인 검토, 생성 이미지/시드, 매뉴얼과 실행 인계가 필요하다.
- 최종 시안 선택은 사람이 한다. 선택 대기는 전체 구현/검증 완료와 구분한다.
