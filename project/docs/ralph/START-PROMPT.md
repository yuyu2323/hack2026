# 구현 시작 프롬프트

> 사용자가 별도로 구현 시작을 지시할 때 사용할 텍스트다. 사전 문서 준비 중에는 실행하지 않는다. 실행 시간/사용량 한계는 시작할 때 사용자가 정한 값과 실제 환경을 따른다.

ShelfDoc 랄프톤 구현을 시작한다. 루트 AGENTS.md, docs/00-vision.md, docs/11-ralphthon-runbook.md, docs/ralph/STATUS.md, docs/ralph/work-packages.md를 읽고 W00부터 진행하라. 00-vision.md는 수정하지 않는다.

로컬 AI 서버는 반드시 구현한다. 제출 사진·질문·병합 가이드라인·Reference 실제 이미지를 로컬 Codex CLI로 분석하고 JSON Schema에 맞춘 질문 답변·기준별 pass/fail/unknown·사진 근거·개선 행동을 반환해야 한다. CLI 실행 어댑터를 분리하고 평문 라벨 파싱을 사용하지 않는다. docs/04-api-contract.md, docs/07-ai-review-spec.md, docs/12-local-ai-server.md를 따르고 Mock을 실제 분석 완료로 보고하지 않는다.

독립 패키지는 서브 에이전트에 배정하고, 조정자는 계약·소유권·통합·진행 기록을 관리하라. 같은 파일을 동시에 수정하지 말고 모델/마이그레이션 작성자는 한 명만 둔다. 큰 패키지를 세분화하고 독립 작업마다 새 서브 에이전트를 생성하라. 구현과 독립 검토는 다른 에이전트에게 배정하고, 완료된 작업자의 슬롯에 다음 작업을 이어서 배정하라. 세션 시간/생성 수 기록·집계 기능은 만들지 않는다.

구현→검증→수정→상태 기록을 반복하며 Must를 먼저 완성하고 Should로 진행하라. 막힌 작업은 원인과 다음 행동을 남기고 가능한 독립 작업을 계속하라. 컨텍스트 전환 전에 재개 정보를 갱신하라. 주 조정 세션을 유지하며 Must 완료 후에도 Should·독립 검토·발견 결함 수정·미검증 시나리오·품질 개선으로 이어가라. 첫 성공이나 한 패키지 완료만으로 종료하지 않는다.

완료 판단은 docs/09-acceptance-tests.md의 실제 증거로 한다. 시작 시 합의한 종료 시각/사용량 한계 또는 사용자 중단을 지키고, 마지막에는 완료·미완료·검증 결과·실행 방법를 인계하라.
