# 구현 작업 패키지

> 전부 계획이며 아직 구현 완료로 표시하지 않는다. 실행 상태는 [STATUS.md](./STATUS.md)에만 기록한다. P0=핵심 Must, P1=Should, P2=범위 내 품질 개선. 구현 시작 지시 후 사용한다.

## 배정 규약

각 패키지는 `ID / 목표 / 입력 문서 / 허용 경로 / 선행 ID / 완료 증거 / 차단 원인 / 다음 행동`을 가진다. 공통 입력은 루트 AGENTS, 00 비전, 04 계약, 05 플레이북이다. 아래 표의 추가 문서는 `docs/` 기준이다. 완료 보고에는 변경 파일, 검사 명령과 결과, 남은 위험을 포함한다. 쓰기 소유권은 조정자가 부여하고 중복 배정하지 않는다.

## 병렬 배치 예시

조정자 외 3개 슬롯인 경우 W01/W02/W03부터 진행한다. 먼저 빈 슬롯에 W04를 배정하고, 이후 준비된 패키지를 순서대로 배정한다. UI는 계약 Mock으로 개발할 수 있지만 W09/W10 완료에는 실제 API가 필요하다. W18은 독립 검토자에게 배정하며 동일 작성 경로를 점유하지 않는다.

상위 W00~W19는 기능 게이트다. 실제 배정은 아래 하위 작업 단위로 나누고 독립 작업마다 새 서브 에이전트를 생성하는 것을 기본으로 한다. 같은 작업의 짧은 보완만 기존 담당자에게 맡긴다. 시간/생성 수 계측 기능은 두지 않는다.

## 확장 배정표 — 작은 작업을 연속 배정

각 셀은 별도로 배정할 수 있는 구체적 작업이다. 부모 패키지의 선행 조건을 그대로 상속한다. 구현 B가 구현 A를 사용하는 경우 A 이후 배정하고, 검토는 검토 대상 구현 이후 새 에이전트에 맡긴다. 각 작업은 해당 산출물과 관련 검사 결과를 제출한다. 모든 셀을 한꺼번에 실행하라는 뜻은 아니다.

| 부모 | 구현 A | 구현 B 또는 시나리오 검증 | 별도 에이전트의 독립 검토 |
|---|---|---|---|
| W02 | 이미지·질문·기준·Reference 입력 조립 | 실제 AI 실행·최종 답변 추출·오류 변환 | 사진 역할 혼동·질문 답변 누락 검토 |
| W03 | 점주 로그인·역할 라우팅 | 단일/다중 매장 선택·빈 상태 | 모바일 진입 흐름 검토 |
| W04 | 관리자 로그인·레이아웃 | 최소 대시보드·담당 매장 화면 | 관리자 역할별 진입 검토 |
| W05 | 인증·토큰 갱신·계정 조회 | 매장 목록·등록 후보·담당 매핑 | 교차 계정 조회와 등록 경합 검토 |
| W06 | 가이드라인 등록·버전·병합 | Reference 업로드·조회·선택 | 계층 우선순위·타 매장 이미지 제외 검토 |
| W07 | 가상 계정·가이드라인·히스토리 시드 | Golden 입력·기대값·검증 상태 정의 | 시드 재실행·데이터 모순 검토 |
| W08 | 제출 저장·작업 점유·상태 전이 | Codex 어댑터·JSON/참조 검증·기준별 결과 저장 | 중복 저장·타임아웃·재시작 복구 검토 |

W01의 모델/마이그레이션은 한 작성자가 순차 진행한다. 이 작업을 여러 작성자에게 쪼개지 않고 읽기 전용 스키마 검토만 별도로 배정한다. 새 하위 작업은 부모 ID에 a/b/review 같은 접미사를 붙여 진행 상태에서 식별한다.

## 기본 기능 이후에도 이어갈 후속 작업

Must를 통과하면 W13~W17을 진행한다. 동시에 W18을 아래 독립 관점으로 나눠 새 검토자에게 배정한다. 아직 확인하지 않은 항목을 선택하고 발견한 결함마다 수정 범위가 명확한 후속 작업을 만든다.

* 점주 모바일: 375px 화면, 카메라/파일 선택, 긴 질문, 뒤로가기 후 상태 복원.
* 관리자 데스크톱: 긴 표·빈 목록·필터 조합·등록 일부 실패 안내.
* 접근성: 키보드 이동·입력 라벨·초점·색 외 상태 표현.
* AI 품질: 질문 미응답·관찰 근거 누락·Reference 혼동·판단 불가 처리.
* 복구: API 재접속·작업자 재시작·중복 요청·이미 종료된 결과 덮어쓰기.
* 성능: 실제 지연의 원인을 구분하고 큰 이미지 처리·불필요한 API 호출을 개선.
* 재현성: 문서대로 초기 구성→시드→실제 제출→관리자 확인까지 시연.

검토와 수정 이후 영향받은 검사를 수행하고 다음 미완료 작업을 배정한다. W19의 최종 인계는 진행한 Should와 후속 수정까지 포함해 갱신한다. 조정 세션은 이 백로그를 계속 순회하되 남은 유효 작업이 없거나 사용자 종료 조건에 도달하면 마무리한다.
